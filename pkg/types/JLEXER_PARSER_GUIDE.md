# JLexer Parser Guide

This document is a **self-contained reference** for writing jlexer streaming parsers. Code examples use fictional structs (e.g. `Request`, `Item`, `Block`) purely to demonstrate patterns — they don't depend on any real struct definitions. Readers (including AI readers) need only read this document to master the full usage.

> For real implementations, see `pkg/types/anthropic/messages_request_jlexer.go` etc. Those structs may evolve with the API; the examples here are not affected.

## Why jlexer

jlexer is the low-level streaming JSON lexer from [easyjson](https://github.com/mailru/easyjson). Unlike `encoding/json` (reflection-based field filling) and `fastjson` (builds an intermediate value tree then accesses it), jlexer **scans the JSON byte stream token by token, writing directly into target struct fields** with no intermediate representation.

### Performance comparison

The following data is from a benchmark in this project (Apple M2), parsing 4 payload variants of the same streaming chunk struct:

| Payload | encoding/json | fastjson | sonic | **jlexer** |
|---|---|---|---|---|
| Simple (TextDelta) | 2224 ns, 23 allocs | 1500 ns, 25 allocs | 1432 ns, 18 allocs | **524 ns, 10 allocs** |
| Nested (ToolCall) | 4139 ns, 32 allocs | 1913 ns, 36 allocs | 3349 ns, 26 allocs | **954 ns, 15 allocs** |
| With usage (FinalChunk) | 3602 ns, 22 allocs | 2572 ns, 35 allocs | 1120 ns, 15 allocs | **958 ns, 12 allocs** |
| Polymorphic (ArrayContent) | 8432 ns, 65 allocs | 2538 ns, 42 allocs | 6656 ns, 59 allocs | **903 ns, 18 allocs** |

jlexer is the fastest in all scenarios (4–9x faster than std) with the fewest allocations. Reasons:
- **No value-tree overhead** (87% of fastjson's allocations are in value-tree construction)
- **No reflection** (both std and sonic rely on reflection for interface dispatch)
- **No JIT compilation overhead** (sonic's JIT has startup cost on simple payloads)

## Prerequisite: octollm.Parser interface and JSONParser[T]

```go
// pkg/octollm/request.go
type Parser interface {
    Parse(data []byte) (any, error)
    Serialize(v any) ([]byte, error)
}
```

```go
// pkg/octollm/json_parser.go
type JLexerParser interface {
    ParseJLexer(in *jlexer.Lexer)
}

type JSONParser[T any] struct{}

func (p *JSONParser[T]) Parse(data []byte) (any, error) {
    // [DONE] sentinel handling ...
    v := new(T)
    switch jlparser := any(v).(type) {
    case JLexerParser:          // If T implements ParseJLexer, use jlexer fast path
        in := jlexer.Lexer{Data: data}
        jlparser.ParseJLexer(&in)
        if err := in.Error(); err != nil {
            return nil, err
        }
        return v, nil
    default:                    // Otherwise fall back to standard json.Unmarshal
        err := json.Unmarshal(data, v)
        // ...
    }
}
```

`JSONParser[T]` auto-dispatches via Go's structural typing: if `T` implements `ParseJLexer(*jlexer.Lexer)`, the jlexer fast path is used; otherwise it falls back to `json.Unmarshal`. **The types package only needs to write `ParseJLexer` methods — it doesn't need to care about the Parser entry point.**

## Circular dependency problem

The `pkg/octollm` package (via `handler.go`) imports `pkg/types/openai`, so `pkg/types/openai` **cannot** import `octollm` back.

**Solution:** The types package only provides `ParseJLexer` methods (no `octollm` import). The Parser entry point (`Parse`/`Serialize`) is centrally implemented in `pkg/octollm/json_parser.go`'s generic `JSONParser[T]`. Go's structural typing means that as long as `T` has a `ParseJLexer(*jlexer.Lexer)` method, `JSONParser[T]` automatically uses the jlexer path — no explicit interface declaration needed.

`ErrStreamDone` and `[DONE]` sentinel handling are also centrally implemented in `json_parser.go`; the types package doesn't need to worry about them.

  <group>_jlexer.go                      <- ParseJLexer methods

## Core design: methods, not free functions

`ParseJLexer` is defined as a method on the struct (in the same package as the struct definition), not as a free function:

```go
// Unified signature: receiver is pre-allocated; the method reads from the lexer and fills fields
func (x *Xxx) ParseJLexer(in *jlexer.Lexer)
```

The method **does not return an error**. jlexer uses an "error accumulation" model — the lexer internally records a `fatalError`, and the caller checks `in.Error()` once after parsing completes. This eliminates per-field error handling, making the code cleaner.

For polymorphic dispatch that returns an interface value (Kind 2/3), use a free function (since methods must be bound to concrete types). The naming convention is `parse<InterfaceName>JLexer` with the signature `func parse<InterfaceName>JLexer(in *jlexer.Lexer) <InterfaceType>`:

```go
// Fictional interface — for demonstrating the naming convention
type Content interface { isContent() }

// Kind 2/3 polymorphic dispatch function: parse + InterfaceName + JLexer
// Returns the interface type; the caller assigns directly to the field
func parseContentJLexer(in *jlexer.Lexer) Content {
    switch in.CurrentToken() {
    // ...
    }
}
```

The caller invokes it in one line within a switch case:

```go
case "content":
    r.Content = parseContentJLexer(in)
```

## How jlexer works

jlexer is a **single-pass streaming lexer**. It maintains a `pos` cursor over `Data []byte`; each read method call advances the cursor and returns the token value. **Once a token is consumed, it cannot be rewound** — this is the fundamental difference from fastjson's value-tree model.

```
Data:  {"id":"abc-123","count":42}
              ↑ pos
      in.UnsafeFieldName() -> "id", pos advances to ':'
      in.WantColon()         -> sets expectation ':'
      in.String()            -> "abc-123", pos advances to ','
      in.WantComma()         -> sets expectation ','
      in.UnsafeFieldName() -> "count", pos advances to ':'
      ...
```

## Writing steps

### Step 1 — Write a ParseJLexer method for each struct

#### Object parsing template

Every struct's `ParseJLexer` method follows the standard easyjson-generated template. Here's a demonstration using a fictional `Request`:

```go
// Fictional struct — for demonstration only
type Request struct {
    Model  string  `json:"model"`
    Count  int     `json:"count"`
    Score  float64 `json:"score"`
}

func (r *Request) ParseJLexer(in *jlexer.Lexer) {
    isTopLevel := in.IsStart()       // Record whether this is a top-level call
    if in.IsNull() {                 // Handle null
        if isTopLevel {
            in.Consumed()
        }
        in.Skip()
        return
    }
    in.Delim('{')                    // Consume '{'
    for !in.IsDelim('}') {           // Loop until '}'
        key := in.UnsafeFieldName(false)  // Read field name (zero-copy)
        in.WantColon()               // Expect ':'
        switch key {
        case "model":
            r.Model = in.String()
        case "count":
            r.Count = in.Int()
        case "score":
            r.Score = in.Float64()
        default:
            in.SkipRecursive()       // Skip unknown fields (forward compatibility)
        }
        in.WantComma()               // Expect ','
    }
    in.Delim('}')                    // Consume '}'
    if isTopLevel {
        in.Consumed()                // Top-level: verify no trailing garbage
    }
}
```

**Every method shares the same 6-step skeleton**: `IsStart` -> `IsNull` check -> `Delim('{')` -> `for` loop -> `Delim('}')` -> `Consumed`. Once you understand this template, you only need to focus on the `switch` body for field handling.

### Step 2 — Write switch cases by field type

| Go field type | JSON form | Code pattern |
|---|---|---|
| `string` | `"hello"` | `r.Field = in.String()` |
| `int` / `int64` | `42` | `r.Field = in.Int()` / `in.Int64()` |
| `bool` | `true` | `r.Field = in.Bool()` |
| `float64` | `3.14` | `r.Field = in.Float64()` |
| `*string` | `"hello"` or `null` or absent | IsNull check -> nil or `&v` |
| non-pointer `string` (may be null) | `"hello"` or `null` | IsNull check -> `""` or `in.String()` |
| `*Struct` | `{...}` or `null` | IsNull check -> nil or allocate + recursive ParseJLexer |
| `[]*Struct` | `[{...}]` or `null` | IsNull check -> nil or Delim('[') + loop |
| `json.RawMessage` | any JSON | `json.RawMessage(in.Raw())` |
| polymorphic interface (Kind 2) | string or array | `switch in.CurrentToken()` dispatch |
| polymorphic interface (Kind 3) | object with `type` | two-pass `Raw()` dispatch |

#### string field

```go
case "name":
    r.Name = in.String()
```

`in.String()` reads the current token and returns a string. If the token is not a string, the lexer records an error but returns `""` (no panic).

#### int field

```go
case "count":
    r.Count = in.Int()
```

#### *string field (nullable)

```go
case "label":
    if in.IsNull() {
        in.Skip()
        r.Label = nil
    } else {
        v := in.String()
        r.Label = &v
    }
```

You must check `in.IsNull()` before `in.String()`, because a `null` token is not a string.

#### Non-pointer string field (may be null)

When a string field is not a pointer (e.g. `Status string` with `omitempty`), the JSON may contain `null`. `json.Unmarshal(null, &str)` succeeds and sets `str` to `""`, but jlexer's `in.String()` will **error** on a `null` token. You must handle this explicitly:

```go
case "status":
    if in.IsNull() {
        in.Skip()
        r.Status = ""
    } else {
        r.Status = in.String()
    }
```

> **Rule:** Any non-pointer string/int/bool/float field that might receive `null` in JSON must be guarded by an `in.IsNull()` check. Pointer fields follow the same rule but set to `nil` instead of the zero value.

#### *Struct field (nullable)

```go
// Fictional struct
type Meta struct {
    UserID string `json:"user_id"`
}

func (m *Meta) ParseJLexer(in *jlexer.Lexer) { /* same template */ }

// In the parent struct's switch:
case "meta":
    if in.IsNull() {
        in.Skip()
        r.Meta = nil
    } else {
        r.Meta = &Meta{}
        r.Meta.ParseJLexer(in)
    }
```

The pointer field is allocated before parsing, then `in` is passed directly to the sub-method. The sub-method continues reading from the lexer's current position, naturally implementing recursive descent.

#### []*Struct array field

```go
// Fictional struct
type Item struct {
    Name string `json:"name"`
}

func (i *Item) ParseJLexer(in *jlexer.Lexer) { /* same template */ }

// In the parent struct's switch:
case "items":
    if in.IsNull() {
        in.Skip()
        r.Items = nil
    } else {
        in.Delim('[')
        if !in.IsDelim(']') {
            r.Items = make([]*Item, 0, 4)
        } else {
            r.Items = []*Item{}
        }
        for !in.IsDelim(']') {
            item := &Item{}
            item.ParseJLexer(in)
            r.Items = append(r.Items, item)
            in.WantComma()
        }
        in.Delim(']')
    }
```

Key points:
- `in.Delim('[')` consumes `[`
- Empty array `[]` returns a non-nil empty slice `[]Xxx{}` (matches `json.Unmarshal`)
- `null` returns a nil slice (matches `json.Unmarshal`)
- Call `in.WantComma()` after each element
- Finally `in.Delim(']')` consumes `]`

#### json.RawMessage field

```go
case "input":
    if in.IsNull() {
        in.Skip()
        r.Input = json.RawMessage("null")
    } else {
        r.Input = json.RawMessage(in.Raw())
    }
```

`in.Raw()` returns the raw bytes of the current value (zero-copy slice pointing into the original buffer), skipping the entire value before returning. For `null`, assign `json.RawMessage("null")` to match `json.Unmarshal` behavior.

### Step 3 — Write ParseJLexer methods for nested structs

Every nested struct gets its own `ParseJLexer` method using the same Object parsing template. Named slice types (e.g. `type ItemArray []*Item`) can define methods, but it's more common to use free functions for polymorphic dispatch (see below).

## Handling polymorphic fields

The project uses three polymorphic field patterns described in `UNION_TYPES.md`. jlexer has different strategies for each. The examples below all use fictional types for self-contained demonstration.

### Kind 1: Has a `type` field, single struct holds all variants

All variant fields can coexist in one struct (no type conflicts). **No dispatch needed** — each field is read independently, and absent fields are automatically zero-valued:

```go
// Fictional struct — text and image variants share one struct
type ContentItem struct {
    Type     string   `json:"type"`           // "text" or "image"
    Text     string   `json:"text,omitempty"`
    ImageURL string   `json:"image_url,omitempty"`
}

func (c *ContentItem) ParseJLexer(in *jlexer.Lexer) {
    // ... standard template ...
    switch key {
    case "type":
        c.Type = in.String()
    case "text":
        c.Text = in.String()
    case "image_url":
        c.ImageURL = in.String()
    default:
        in.SkipRecursive()
    }
    // ...
}
```

The `type` field is just an ordinary string field, on equal footing with all other fields. Regardless of where `type` appears in the JSON, it's always read correctly.

### Kind 2: No `type` field, same key can be different JSON types

The same JSON key can be a string, array, or object with no common discriminator. Use `in.CurrentToken()` to **peek at the current token type** (without consuming), then `switch` to dispatch.

The following fictional example demonstrates string-vs-array polymorphism:

```go
// Fictional interface and concrete types
type Content interface{ isContent() }

type ContentString string
func (ContentString) isContent() {}

type ContentArray []*ContentItem
func (ContentArray) isContent() {}

// parseContentJLexer handles Kind 2 polymorphism: can be string or array
func parseContentJLexer(in *jlexer.Lexer) Content {
    switch in.CurrentToken() {
    case jlexer.TokenString:
        return ContentString(in.String())
    case jlexer.TokenNull:
        in.Skip()
        return nil
    case jlexer.TokenDelim:
        if in.IsDelim('[') {
            in.Delim('[')  // Consume '['
            var arr ContentArray
            if !in.IsDelim(']') {
                arr = make(ContentArray, 0, 4)
            } else {
                arr = ContentArray{}
            }
            for !in.IsDelim(']') {
                item := &ContentItem{}
                item.ParseJLexer(in)
                arr = append(arr, item)
                in.WantComma()
            }
            in.Delim(']')
            return arr
        }
        in.SkipRecursive()
        return nil
    default:
        in.SkipRecursive()
        return nil
    }
}
```

The caller invokes it in one line:

```go
case "content":
    r.Content = parseContentJLexer(in)
```

String-vs-object polymorphism works the same way — the `TokenDelim` branch checks `{` instead of `[`:

```go
// parseRefJLexer handles Kind 2 polymorphism: can be string or object
func parseRefJLexer(in *jlexer.Lexer) RefValue {
    switch in.CurrentToken() {
    case jlexer.TokenString:
        return RefString(in.String())
    case jlexer.TokenNull:
        in.Skip()
        return nil
    case jlexer.TokenDelim:
        if in.IsDelim('{') {
            obj := &RefObject{}
            obj.ParseJLexer(in)
            return obj
        }
        in.SkipRecursive()
        return nil
    default:
        in.SkipRecursive()
        return nil
    }
}
```

**Why Kind 2 has no field-ordering problem in jlexer:** Kind 2 dispatch is based on the **JSON token type** (string vs array vs object), not on a field value inside a JSON object. The token type is determined the moment the lexer reaches the value — no lookahead needed.

### Kind 3: Has a `type` field, but variants have field type conflicts

The JSON object has a `type` field, but different variants use incompatible Go types for the same JSON key, making a single struct impossible. **This is the only scenario requiring special handling in jlexer** — because the `type` field may appear after type-specific fields, and jlexer is streaming, so it can't rewind.

#### The problem

```json
{"text": "Hello", "citations": [...], "type": "text"}
```

When the lexer reads `text` and `citations`, it doesn't yet know the value of `type` and can't decide which concrete struct to parse into. By the time `type` is read, the preceding fields have already been consumed.

#### Fictional example

```go
// Fictional interface and concrete types — the citations field is []string in TextBlock
// but *bool in DocBlock — type conflict, can't share one struct
type Block interface{ isBlock() }

type TextBlock struct {
    Type       string      `json:"type"`       // "text"
    Text       string      `json:"text"`
    Citations  []string    `json:"citations,omitempty"`
}
func (*TextBlock) isBlock() {}

type DocBlock struct {
    Type       string      `json:"type"`       // "doc"
    Title      string      `json:"title"`
    Citations  *bool       `json:"citations,omitempty"`  // same key, different type!
}
func (*DocBlock) isBlock() {}

type GenericBlock struct {
    Type string `json:"type"`  // fallback
}
func (*GenericBlock) isBlock() {}
```

#### Solution: two-pass `Raw()` scan

```go
// parseBlockJLexer handles Kind 3 polymorphism
func parseBlockJLexer(in *jlexer.Lexer) Block {
    if in.IsNull() {
        in.Skip()
        return nil
    }
    // Step 1: capture the current object's raw bytes using in.Raw()
    // Raw() internally calls SkipRecursive() to advance the cursor, then returns r.Data[r.start:r.pos] — zero-copy
    rawBytes := in.Raw()

    // Step 2 (first pass): create a new Lexer, scan only for the type field, skip everything else
    blockType := extractTypeField(rawBytes)

    // Step 3 (second pass): create a new Lexer, dispatch to the concrete type's ParseJLexer based on type
    parseLex := jlexer.Lexer{Data: rawBytes}
    switch blockType {
    case "text":
        b := &TextBlock{}
        b.ParseJLexer(&parseLex)
        return b
    case "doc":
        b := &DocBlock{}
        b.ParseJLexer(&parseLex)
        return b
    default:
        b := &GenericBlock{}  // fallback
        b.ParseJLexer(&parseLex)
        return b
    }
}
```

`extractTypeField` is a fast scan function — it iterates the object's fields, reading only the value of `type` and `SkipRecursive()`-ing everything else:

```go
func extractTypeField(data []byte) string {
    lex := jlexer.Lexer{Data: data}
    lex.Delim('{')
    for !lex.IsDelim('}') {
        key := lex.UnsafeFieldName(false)
        lex.WantColon()
        if key == "type" {
            return lex.String()
        }
        lex.SkipRecursive()
        lex.WantComma()
    }
    return ""
}
```

#### Performance analysis

The two-pass overhead is small (benchmark: ~684 ns vs ~135 ns single-pass):
- `in.Raw()` is zero-copy — returns a slice pointing into the original buffer
- The first pass only scans bytes + `SkipRecursive()`, building no structs
- The second pass does real field parsing, identical to normal parsing
- `type` position (first vs last) makes almost no difference (625 ns vs 684 ns) — the first pass must scan to `type` regardless
- Only 1 extra allocation (the rawBytes slice header)

#### Comparison with fastjson

fastjson handles Kind 3 by building a value tree first, then querying `v.GetStringBytes("type")`. Value-tree construction has a fixed cost (~1500+ ns), while jlexer's two-pass scan totals ~684 ns — still significantly faster.

### Three kinds of polymorphism compared

| | Kind 1 (single struct) | Kind 2 (no type field) | Kind 3 (type + field conflicts) |
|---|---|---|---|
| JSON characteristic | Has `type`, no field conflicts | No `type`, same key with different JSON types | Has `type`, but field types conflict |
| Dispatch method | No dispatch, read fields independently | `switch in.CurrentToken()` | Two-pass `Raw()` + `switch type` |
| Field ordering problem | None | **None** (token type is immediate) | **Yes**, solved by two-pass scan |
| Fallback needed | No | Unmatched token -> `SkipRecursive` | Yes, e.g. `GenericBlock` catch-all |

## jlexer API quick reference

### Object operations

| Method | Description |
|---|---|
| `in.Delim('{')` | Consume and validate `{` |
| `in.Delim('}')` | Consume and validate `}` |
| `in.IsDelim('}')` | Check if current token is `}` (no consume) |
| `in.Delim('[')` / `in.Delim(']')` | Same, for arrays |
| `in.IsDelim(']')` | Check if current token is `]` (no consume) |
| `in.UnsafeFieldName(false)` | Read field name (zero-copy, may point into original buffer) |
| `in.WantColon()` | Set expectation that next token is preceded by `:` |
| `in.WantComma()` | Set expectation that next token is preceded by `,` |

### Value readers

| Method | Return value | Description |
|---|---|---|
| `in.String()` | `string` | Read a string token |
| `in.Int()` | `int` | Read a number token |
| `in.Int64()` | `int64` | Read a number token |
| `in.Float64()` | `float64` | Read a number token |
| `in.Bool()` | `bool` | Read a true/false token |

### Control

| Method | Description |
|---|---|
| `in.IsNull()` | Check if current token is null (no consume) |
| `in.Skip()` | Skip the current single token |
| `in.SkipRecursive()` | Skip the current value (recursively for object/array) |
| `in.CurrentToken()` | Peek at the current token type (no consume), for Kind 2 dispatch |
| `in.Raw()` | Capture the current value's raw bytes (zero-copy), for Kind 3 two-pass scan |
| `in.IsStart()` | Whether at the buffer start position |
| `in.Consumed()` | Verify no trailing characters (used after top-level call) |
| `in.Ok()` | Whether there are no errors |
| `in.Error()` | Get the accumulated error |

### TokenKind constants (for `CurrentToken()`)

`TokenUndef` · `TokenDelim` · `TokenString` · `TokenNumber` · `TokenBool` · `TokenNull`

### The IsStart / Consumed pattern for top-level calls

Every `ParseJLexer` method records `isTopLevel := in.IsStart()` at the top, and checks `if isTopLevel { in.Consumed() }` at the end. This is because jlexer can be called at any position; only top-level calls need to ensure the entire buffer is consumed (no trailing garbage). Nested calls (from a parent object's switch case) don't need `Consumed`.

## Aligning with standard json.Unmarshal behavior

The parser must produce results identical to `json.Unmarshal`, including edge cases:

| JSON situation | json.Unmarshal behavior | jlexer parser should do |
|---|---|---|
| Key absent | Field keeps zero value | No case matches -> `SkipRecursive`; or the case is never entered |
| `"key": null` (pointer field) | Pointer/slice is nil | `in.IsNull()` -> `in.Skip()` + set to nil |
| `"key": null` (non-pointer string) | String field is `""` | `in.IsNull()` -> `in.Skip()` + set to `""` |
| `"key": ""` | String field is `""` | `in.String()` returns `""` |
| `"key": []` | Slice is non-nil empty slice | `IsDelim(']')` is true -> `[]Xxx{}` |
| `"key": [null]` | Slice contains nil elements | Element `in.IsNull()` -> `in.Skip()`, append nil |
| Unknown key | Ignored | `default: in.SkipRecursive()` |

## Testing strategy

Compare `ParseJLexer` output with standard `json.Unmarshal` output field-by-field (`assert.Equal`). Test files don't go through the `JSONParser` entry; instead they create a `jlexer.Lexer` directly and call `ParseJLexer`, avoiding a circular dependency on the `octollm` package:

```go
func TestRequestJLexer_Parse(t *testing.T) {
    testCases := []struct {
        Name string
        JSON string
    }{
        {Name: "Basic", JSON: `{"model":"gpt-4","count":10}`},
        {Name: "Empty", JSON: `{}`},
        {Name: "NullField", JSON: `{"model":null}`},
        // ... cover all field types and edge cases
    }

    for _, tc := range testCases {
        t.Run(tc.Name, func(t *testing.T) {
            var stdReq, jReq Request
            err := json.Unmarshal([]byte(tc.JSON), &stdReq)
            require.NoError(t, err)

            in := jlexer.Lexer{Data: []byte(tc.JSON)}
            jReq.ParseJLexer(&in)
            require.NoError(t, in.Error())

            assert.Equal(t, stdReq, jReq)
        })
    }
}
```

### Test case coverage checklist

- **Each field type** at least one case: string, int, `*string`, `[]*Struct`, `*Struct`, `json.RawMessage`, polymorphic interface
- **Missing fields**: empty JSON `{}`, verify all fields are zero-valued
- **null values**: pointer/slice is nil; non-pointer string field is `""`
- **Empty array**: `"items": []`, verify slice is non-nil empty slice
- **Polymorphic dispatch**: Kind 2 string and array each one case; Kind 3 each `type` value one case + type in different positions
- **Real API responses**: use captured JSON (with unknown fields) to verify `default: SkipRecursive()` forward compatibility
